## Product

- **Working name:** Snowshoe (provisional; not final brand). **Backup:** Catchmark.
- **Subtitle:** Don't let your agents outrun your understanding. Keep your footing.
- **Wedge:** git-native personal **comprehension map of a repository** (any clone; the *map/ledger* is personal/local, not “only personal GitHub repos”). After commits or `git pull`, show what went stale; the human chooses what to catch up on (agency). Structure exists so the human can explore and rank misunderstanding — not only consume an agent “red queue.”
- **Form (intent):** CLI-first **orchestrator** (not a passive ledger, not a full agent harness). Owns git-anchored state, freshness, and verify protocol; pluggable agent backends are workers for map / explain / quiz. Dual entry: harness skills call `snowshoe …` (PATH binary **`snowshoe`**; informal *snow* is not PATH), or the CLI invokes a configured backend (e.g. a catch-up flow). Details: [ADR-2026-09-25-product-form-orchestrator.md](./DECISIONS/ADR-2026-09-25-product-form-orchestrator.md), [ADR-2026-09-25-provisional-name-snowshoe.md](./DECISIONS/ADR-2026-09-25-provisional-name-snowshoe.md).
- **State default:** project model may live under something like `.snowshoe/`; **personal ledger gitignored / local by default**. **SQLite is source of truth** for FSM / queue / leases / epoch meta / metrics (floats `0.0–1.0`); heavy payloads are files under `.snowshoe/epochs/<epochId>/…`; markdown map/notes are human-readable, **not** SoT for metrics or step statuses. [ADR-2026-09-25-personal-state-gitignore.md](./DECISIONS/ADR-2026-09-25-personal-state-gitignore.md), [ADR-2026-09-25-implementation-stack.md](./DECISIONS/ADR-2026-09-25-implementation-stack.md).
- **v1 surfaces (intent):** primary signal where “red” arrives on delta — **opt-in** local git hook after pull/merge (+ checkout when relevant) and PR-check; navigable map is a **secondary** screen, not the product home. **Default signal:** skill → CLI. Skill entry is `snowshoe work next` (gates `init` / `routine refresh` / `routine advance` via `todo` until clear); families still *proposed*. `init` does **not** install hooks; opt-in hooks remain intent (CLI not shipped). CLI always. Local GUI map is on-demand via `snowshoe map serve` (dumb client of `map status` JSON). Human marks/cancels/reloads in the UI, or this turn asks the agent to `map detail mark` / `cancel` for named nodes; the agent completes via CLI. [ADR-2026-09-25-v1-surfaces.md](./DECISIONS/ADR-2026-09-25-v1-surfaces.md), [ADR-2026-09-27-map-ui-and-skill.md](./DECISIONS/ADR-2026-09-27-map-ui-and-skill.md), [ADR-2026-09-27-skill-drain-loop.md](./DECISIONS/ADR-2026-09-27-skill-drain-loop.md).
- **Implementation:** TypeScript on **Bun**; CLI with citty + Zod; durable machine state **`bun:sqlite`**. Map UI: React + Vite, served by `snowshoe map serve` (loopback bind only; PTY and all `/api/*` require loopback `Host`, matching loopback Origin, and a per-launch access token; HTML CSP `default-src 'self'` + loopback `ws:` `connect-src` + `Referrer-Policy: no-referrer` — [ADR-2026-10-08-map-serve-origin-token.md](./DECISIONS/ADR-2026-10-08-map-serve-origin-token.md); HTTP twins share the CLI read/mutation layer). NestJS / Next.js / Electron are out of day-1. Install bin is **`snowshoe`**; informal *snow* is not PATH. Detail complete: `children` (parent→child) + `refs` (relevance); missing/moved anchors reject; upserts require non-empty `body` / `bodyMd` or existing `proseRef` prose (first paragraph = overview; `bodyOverview` is a derived map-status field). `init --locale` (BCP-47) persists ledger meta; map status / session / `work next` expose it. Map inspector renders resolved `bodyMd` (wiki `[[slug]]` / `[[slug|label]]` navigate in-UI; missing targets styled broken; not auto-`refs`) and navigable `refs`; in-UI code preview via `GET /api/file` (repoRoot sandbox); `vscode://` is secondary. The left column is a nav pane with tabs **Tree** / **Graph** (radial 1-hop ego over the same `MapReadModel`; visit prev/next as ↺/↻ badges with left/right layout and arc reflow; History back/forward on those clicks) / **Todos** (Inbox: system `new`/`decayed`; Later: personal `learn`/`quiz`; leave-node / Read all clear inbox only); tab choice in `sessionStorage` (`snowshoe.navTab`). The map tree is collapsible; `map serve --expand-depth` (default **1**) expands root only at start; click selects, double-click expands/collapses; tree / inspector / sidebar columns are mouse-resizable; arrow keys walk the tree when the Tree tab is active (←/→ collapse/expand; no click required unless code preview is focused). Header SHA is the map epoch **target** (or HEAD if none); red when `refreshRequired`. Breadcrumbs show the parent chain; the URL hash is Back/Forward. Optional in-memory `GET /api/view/:id` mirrors the focused slug (not the ledger, not the skill loop). `snowshoe map view` re-reads that JSON via `SNOWSHOE_MAP_URL` / `SNOWSHOE_VIEW` / `SNOWSHOE_MAP_TOKEN`. Map sidebar may embed a **loopback-peer** PTY (not chat, not HITL, not a shipped quiz). The PTY prints a welcome inviting the human’s agent + snowshoe skill; env includes `SNOWSHOE_MODE=learn` and `SNOWSHOE_MAP_TOKEN`. The printed / `--open` URL carries the token in the fragment (`#t=`). PTY shells are keyed by map `viewId` and **survive WebSocket drops** (laptop sleep): the UI auto-reconnects and replays a short buffer; **Restart** (or `?reset=1`) spawns a fresh shell; orphans are reaped after 12h idle and capped at 4 shells per `map serve` (oldest detached first) ([ADR-2026-09-29-map-pty-channel.md](./DECISIONS/ADR-2026-09-29-map-pty-channel.md)). Map UI files come from the running snowshoe package (`bun link` target), not cwd. The map UI polls that JSON and highlights **Reload** when the shown snapshot is stale (does not auto-apply). Default `work next --batch-size` is 5. `work next --wait` (optional `--wait-timeout <ms>`) blocks only while `action` would be `idle`: wakes on `.snowshoe/` filesystem events, 2s fallback tick — not a daemon; skill uses it only when the human asked to drain map marks interactively.
