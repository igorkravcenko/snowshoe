## Product

- **Working name:** Snowshoe (provisional; not final brand). **Backup:** Catchmark.
- **Subtitle:** Catch up after pull.
- **Wedge:** git-native / ideally OSS layer for a *personal* repo comprehension map. After commits or `git pull`, show what went stale; the human chooses what to catch up on (agency). Structure exists so the human can explore and rank misunderstanding — not only consume an agent “red queue.”
- **Form (intent):** CLI-first **orchestrator** (not a passive ledger, not a full agent harness). Owns git-anchored state, freshness, and verify protocol; pluggable agent backends are workers for map / explain / quiz. Dual entry: harness skills call `snowshoe …` (PATH binary **`snowshoe`**; informal *snow* is not PATH), or the CLI invokes a configured backend (e.g. a catch-up flow). Details: [ADR-2026-09-25-product-form-orchestrator.md](./DECISIONS/ADR-2026-09-25-product-form-orchestrator.md), [ADR-2026-09-25-provisional-name-snowshoe.md](./DECISIONS/ADR-2026-09-25-provisional-name-snowshoe.md).
- **State default:** project model may live under something like `.snowshoe/`; **personal ledger gitignored / local by default**. **SQLite is source of truth** for FSM / queue / leases / epoch meta / metrics (floats `0.0–1.0`); heavy payloads are files under `.snowshoe/epochs/<epochId>/…`; markdown map/notes are human-readable, **not** SoT for metrics or step statuses. [ADR-2026-09-25-personal-state-gitignore.md](./DECISIONS/ADR-2026-09-25-personal-state-gitignore.md), [ADR-2026-09-25-implementation-stack.md](./DECISIONS/ADR-2026-09-25-implementation-stack.md).
- **v1 surfaces (intent):** primary signal where “red” arrives on delta — **opt-in** local git hook after pull/merge (+ checkout when relevant) and PR-check; navigable map is a **secondary** screen, not the product home. **Default signal:** skill → CLI. Skill entry is `snowshoe work next` (gates `init` / `routine refresh` / `routine advance` via `todo` until clear); families still *proposed*. `init` does **not** install hooks; `hooks install` / `uninstall` are opt-in. CLI always. Local GUI map is on-demand via `snowshoe map serve` (dumb client of `map status` JSON). Human marks/cancels/reloads in the UI, or this turn asks the agent to `map detail mark` / `cancel` for named nodes; the agent completes via CLI. [ADR-2026-09-25-v1-surfaces.md](./DECISIONS/ADR-2026-09-25-v1-surfaces.md), [ADR-2026-09-27-map-ui-and-skill.md](./DECISIONS/ADR-2026-09-27-map-ui-and-skill.md), [ADR-2026-09-27-skill-drain-loop.md](./DECISIONS/ADR-2026-09-27-skill-drain-loop.md).
- **Implementation:** TypeScript on **Bun**; CLI with citty + Zod; durable machine state **`bun:sqlite`**. Map UI: React + Vite, served by `snowshoe map serve` (HTTP twins share the CLI read/mutation layer). NestJS / Next.js / Electron are out of day-1. Install bin is **`snowshoe`**; informal *snow* is not PATH. Detail complete: `children` (parent→child) + `refs` (relevance); missing/moved anchors reject; upserts require non-empty `body` / `bodyMd` or existing `proseRef` prose. `init --locale` (BCP-47) persists ledger meta; map status / session / `work next` expose it. Map inspector renders resolved `bodyMd` and navigable `refs`; in-UI code preview via `GET /api/file` (repoRoot sandbox); `vscode://` is secondary. The left column is a nav pane with tabs **Tree** / **Graph** (radial 1-hop ego over the same `MapReadModel`; previous/next visit borders; History back/forward on those clicks) / **Todos** (nodes with personal `learn`/`quiz` marks); tab choice in `sessionStorage` (`snowshoe.navTab`). The map tree is collapsible; `map serve --expand-depth` (default **1**) expands root only at start; click selects, double-click expands/collapses; tree / inspector / sidebar columns are mouse-resizable; arrow keys walk the tree when the Tree tab is active (←/→ collapse/expand; no click required unless code preview is focused). Header SHA is the map epoch **target** (or HEAD if none); red when `refreshRequired`. Breadcrumbs show the parent chain; the URL hash is Back/Forward. Optional in-memory `GET /api/view/:id` mirrors the focused slug (not the ledger, not the skill loop). `snowshoe map view` re-reads that JSON via `SNOWSHOE_MAP_URL` / `SNOWSHOE_VIEW`. Map sidebar may embed a **loopback-peer** PTY (not chat, not HITL, not a shipped quiz). The PTY prints a welcome inviting the human’s agent + snowshoe skill; env includes `SNOWSHOE_MODE=learn`. Map UI files come from the running snowshoe package (`bun link` target), not cwd. The map UI polls that JSON and highlights **Reload** when the shown snapshot is stale (does not auto-apply). Default `work next --batch-size` is 5. `work next --wait` (optional `--wait-timeout <ms>`) blocks only while `action` would be `idle`: wakes on `.snowshoe/` filesystem events, 2s fallback tick — not a daemon; skill uses it only when the human asked to drain map marks interactively. ## Now

Detail drain hop: grow vs `unchanged` (no child quota; group when a flat list is too large; important children first). `leaf` is a stop-flag (not a type); `symbol` may have children; mark detail on a leaf asks to split further. Mark kinds (`expand` grows the tree; `enrich` improves fields/body; `fix` repairs a wrong area — each has its own work step; `learn` / `quiz` are user-only, not `work next`; the map **Todos** tab lists those personal marks) — not tags ([ADR-2026-10-01-map-polish.md](./DECISIONS/ADR-2026-10-01-map-polish.md), [ADR-2026-10-02-map-nav-tabs.md](./DECISIONS/ADR-2026-10-02-map-nav-tabs.md)). Anchors persist start `lineText` and fragment size; omit guessed `endLine`. Default map split is narrower (`snowshoe.split.v2`). `map status` default columns are `slug` + `children`; `--all-fields` is every column (map UI uses `?allFields=1`); `--fields` is a comma-separated allowlist. `--slug` is focus (alone = that node); `--depth` is a subtree from focus or from `root`; `--neighborhood --slug` is the ego graph (`edges`). Detail complete may enrich the marked node, `retire` descendants, `clearEdges` in-subtree. Locale at init; required entity body on detail upsert; in-UI code preview (first node anchor is preloaded; sidebar tab is not stolen); optional `work next --wait`. Agent may `map mark` / `map detail mark` only if the human asked this turn; `snowshoe help --json` is the agent command index ([ADR-2026-09-30-user-asked-mark-and-help.md](./DECISIONS/ADR-2026-09-30-user-asked-mark-and-help.md)). Optional `snowshoe feedback add` / `remove` and the map Feedback tab (add/delete) use gitignored `.snowshoe/feedback/` (dev inbox, not a v1 surface) ([ADR-2026-09-30-agent-feedback-inbox.md](./DECISIONS/ADR-2026-09-30-agent-feedback-inbox.md)).
